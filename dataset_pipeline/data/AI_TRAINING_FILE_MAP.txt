AI MODEL TRAINING — FILE MAPPING
==================================

STAGE 1: Noise Reduction / Alert Triage (Binary Classification)
---------------------------------------------------------------
Goal: Classify alerts as "noise" vs "important"

File                                   | Key Labels/Features for Training
---------------------------------------|-----------------------------------------------
raw/*.ndjson (all 6 datasets)         | noise (bool), true_positive (bool), event_type, alert_severity, alert_category, attack_type
outputs/soc_dataset_*.ndjson          | noise, true_positive, analyst_verdict, suppression_hit, enrichment_vt_score, enrichment_abuse_score, geoip_src/dst_country
outputs/soc_dataset_*.csv             | noise, true_positive, analyst_verdict, alert_severity, enrichment scores (flat columns)
outputs/llm_datasets/suppression_reasons_*.json | suppression_hit (label), suppression_reason, environment_context, historical_false_positive_rate, recurring_alert
outputs/llm_datasets/analyst_notes_*.json       | analyst_verdict, analyst_notes, noise, true_positive, suppression_hit

Recommended training approach: Use raw + soc_dataset for labeled binary classification.
Use LLM suppression_reasons for fine-tuning an LLM to generate suppression justifications.


STAGE 2: Attack-Type Classification (Multi-Class Classification)
-----------------------------------------------------------------
Goal: Classify alerts into specific attack categories (brute_force, malware, DoS, etc.)

File                                   | Key Labels/Features for Training
---------------------------------------|-----------------------------------------------
raw/*.ndjson (all 6 datasets)         | attack_type (label), mitre_technique_id, mitre_technique_name, mitre_tactic, alert_category, alert_signature, protocol, src_port, dst_port, bytes_sent, bytes_received, duration
outputs/soc_dataset_*.ndjson          | attack_type, alert_category, alert_signature, mitre fields, enrichment scores, cluster_id
outputs/soc_dataset_*.csv             | attack_type, alert_category, mitre_technique_id, mitre_tactic (flat columns)
outputs/llm_datasets/analyst_notes_*.json       | attack_type, alert_signature, analyst_notes (for few-shot / in-context learning)

Recommended training approach: Raw datasets provide ground-truth attack_type labels.
Augment with soc_dataset enriched features for better accuracy.
Use analyst_notes for LLM fine-tuning on attack description generation.


STAGE 3: Risk Scoring (Regression / Ranking)
----------------------------------------------
Goal: Predict a continuous risk score (0-100) and priority level

File                                   | Key Labels/Features for Training
---------------------------------------|-----------------------------------------------
outputs/soc_dataset_*.ndjson          | alert_severity (base), enrichment_vt_score, enrichment_abuse_score, enrichment_epss_score, enrichment_misp_matches, campaign_id, cluster_id, alert_category, playbook_outcome
outputs/soc_dataset_*.csv             | Same features in flat format (27 columns)
outputs/llm_datasets/escalation_decisions_*.json | escalation_level (label), escalation_reason, risk_adjusted_priority, confidence, asset_criticality, repeated_behavior_score, similar_alerts_last_hour, analyst_verdict
outputs/llm_datasets/analyst_notes_*.json       | analyst_verdict, analyst_assigned (for confidence calibration)
raw/*.ndjson                          | alert_severity, confidence (baseline input features)

Recommended training approach: Use soc_dataset features as input, escalation_decisions
for target labels. Train regression model for continuous score + classifier for
priority bins (LOW/MEDIUM/HIGH/CRITICAL). LLM escalation_reasons for explainability.


STAGE 4: Intelligent Playbook Recommendation (Rule Engine + ML Hybrid)
-----------------------------------------------------------------------
Goal: Recommend automated actions (quarantine, block, investigate, log, etc.)

File                                   | Key Labels/Features for Training
---------------------------------------|-----------------------------------------------
outputs/soc_dataset_*.ndjson          | playbook_outcome (label), escalation_level, analyst_verdict, campaign_id, cluster_id, enrichment scores, geoip fields, extra_fields (duplicate_of, fatigue)
outputs/llm_datasets/escalation_decisions_*.json | escalation_level, escalation_reason, analyst_verdict, confidence, risk_adjusted_priority, asset_criticality, repeated_behavior_score
outputs/llm_datasets/analyst_notes_*.json       | analyst_verdict, analyst_notes, analyst_assigned (human decision examples)
outputs/thehive_cases_*.json          | severity, tags, tasks, observables (case-creation patterns for automated response)

Recommended training approach: Rule engine for deterministic decisions
(high severity + high risk → quarantine). ML model for nuanced cases
(medium scores → predict playbook_outcome). Fine-tune LLM on analyst_notes
and escalation_decisions for natural-language action justifications.


STAGE 5: Patching Recommendation (CVE-to-Action Mapping)
----------------------------------------------------------
Goal: Predict which CVEs need patching, assign priority, and recommend action

File                                   | Key Labels/Features for Training
---------------------------------------|-----------------------------------------------
raw/*.ndjson (all 6 datasets)         | alert_signature, description, attack_type, mitre_technique_id (CVE references may appear in descriptions for extraction by intel.py CVE engine)
outputs/soc_dataset_*.ndjson          | enrichment_epss_score (exploit likelihood), enrichment_cvss_score, enrichment_misp_matches, alert_category, attack_type, campaign_id, cluster_id, host_context fields (affected host/OS)
outputs/soc_dataset_*.csv             | enrichment_epss_score, alert_severity, alert_category (flat features for tabular model)
outputs/llm_datasets/analyst_notes_*.json       | analyst_notes, analyst_verdict (free-text patch suggestions from analysts)
External (used at inference, also for training labels):
  NVD API (nvd.nist.gov)             | CVE → CVSS score, affected software, description, severity vector
  EPSS API (api.first.org)           | CVE → EPSS probability (0-1), percentile

Recommended training approach:
  Stage 5a — CVE Relevance: Binary classifier on alert_signature + description
    to detect whether an alert contains a patchable CVE. Train on raw ndjson
    descriptions with known CVE patterns (regex-extracted).
  Stage 5b — Priority Regression: Predict patch priority (CRITICAL/HIGH/MEDIUM/LOW)
    from CVSS + EPSS + alert severity + asset context. Train on NVD/EPSS API outputs
    joined with soc_dataset alerts.
  Stage 5c — Action Generation: LLM fine-tuned on analyst_notes to generate
    human-readable patch action text (e.g., "Apply OpenSSL 3.0.8 or later").
  Inference pipeline: CVE scan → CVSS/EPSS lookup → priority model → LLM action text.
